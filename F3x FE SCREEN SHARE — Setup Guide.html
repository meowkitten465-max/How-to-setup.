Part 1 — Python setup
1

Install Python 3.10 or newer

Download from python.org. During install, tick "Add Python to PATH" — this is required.

⚠️ If you skip "Add to PATH" the launch script won't find Python and nothing will work.
2

Put all three files in the same folder

Create a folder anywhere — Desktop is fine. Drop f3x_screenshare.lua, screen_server.py, and launch.ps1 in it together.

3

Run launch.ps1

Right-click launch.ps1 → Run with PowerShell. It will install the required Python packages automatically, then start the screen server.

# what it installs for you:
websockets   # websocket server
mss          # screen capture
opencv-python-headless  # frame processing
numpy        # pixel math

When it's ready you'll see:

[check] mss        ok
[check] cv2        ok
[check] numpy      ok
[check] websockets ok

[ScreenShare] waiting for Lua client on ws://localhost:8080 ...
✅ Keep this PowerShell window open the whole time. Closing it kills the server and the stream stops.
⚠️ If PowerShell says "execution policy" error, open PowerShell as Administrator and run:

Set-ExecutionPolicy RemoteSigned -Scope CurrentUser

Then try running launch.ps1 again.
Part 2 — Roblox setup
4

Join a Roblox game that has F3X

The game must have the F3X building tool available. Any build-permitted server works.

5

Equip the F3X tool

This is critical — the script finds F3X's SyncAPI by scanning the game. If F3X isn't equipped and loaded, the script errors out. Equip it before running the script.

⚠️ Equip F3X before running the exploit script. Not after.
6

Inject and run f3x_screenshare.lua

Open your executor (Madium, Synapse X, Solara, etc.), attach to Roblox, paste the contents of f3x_screenshare.lua and execute it. The Rayfield GUI will load with the title F3x FE SCREEN SHARE.

Part 3 — Using the GUI
7

Build Screen

In the Control tab, click Build Screen. This creates 1,296 parts in front of your character using 150 concurrent threads. Wait for the notification that says how many parts were built and the time taken.

Build Screen → Notification: "1296 parts in X.Xs — enable stream to go live."
ℹ️ Stand somewhere open before building — the canvas spawns 10 studs up and 80 studs in front of you.
8

Enable Stream

Toggle Enable Stream to ON. This connects to the Python server on ws://127.0.0.1:8080 and starts receiving screen frames. The canvas will start displaying your screen in real time.

Enable Stream ● → Notification: "Stream Live — Receiving screen at 60fps."
⚠️ The Python server (launch.ps1) must already be running before you toggle this on or the connection will fail.
9

Stop / clean up

Use these controls when you're done:

Stop Screen Updates → Freezes the canvas frame. Parts stay, stream pauses.
Enable Stream → OFF → Disconnects from Python server completely.
Settings → Remove Canvas → Deletes all 1,296 parts from the game.
Troubleshooting
SyncAPI not found
You didn't equip F3X before running the script. Equip it, wait 2 seconds, then re-run.
Connection Failed — could not reach Python server
launch.ps1 isn't running, or it crashed. Check the PowerShell window for errors and restart it.
Port 8080 in use
Another program is using port 8080. Close it, or open screen_server.py and change PORT = 8080 to any free port (e.g. 8081). Update WS_URL in the Lua script to match.
Script works but image looks blocky / low quality
That's normal — the canvas is 48×27 pixels by design, each pixel is a 3.5×3.5 stud Neon part. It's a low-res screen share, not a monitor.
Stream is slow / laggy
The visual refresh rate is limited by Roblox's server round-trip (~20–50ms). This is the engine floor — nothing can push past it. The Python side is already at 60fps.
